## 1. Mission & Vision

**Mission:** ReadyOnline empowers young people, parents, and seniors to navigate the digital world safely, confidently, and critically — with age-appropriate tools, real-world guidance, and community accountability built in from the start.

**Vision:** A world where every person — regardless of age or tech comfort level — has the knowledge and support to recognize danger online, make informed decisions, and access help without shame or confusion.

**Core Values:**
- Safety first, always
- Age-appropriate design (no one-size-fits-all)
- Real-world action over passive awareness
- Trust earned through transparency
- Accessibility for all literacy and tech levels

## 2. Click-Through Architecture

The homepage presents three clearly defined audience entry points:

1. **Teens & Young Adults (Ages 13–22)**
2. **Parents & Guardians**
3. **Seniors (Ages 60+)**

Each audience card links to a dedicated module. No user should land on content not designed for their context.

**Global Navigation Elements (present on all pages):**
- ReadyOnline Logo (links to Home)
- Crisis Line button (always visible, top-right, high contrast)
- Language selector
- Accessibility toggle (font size, contrast)
- Footer: About | Privacy Policy | Contact | Accredited Resources

**Click-Through Flow:**

```
Home → Audience Hub → Audience Module → Topic Selection → Content Page → Action Step / Resource / Report Tool
```

Each content page ends with: a takeaway summary, a next-step button, and a link to the feedback form.

## 4. Training System Blueprint

ReadyOnline's training system is modular, sequential, and self-paced. It combines scenario-based learning with reflection checkpoints — not a quiz-only system.

**Structure:**
- Modules are audience-gated (teens see teen content; parents see parent content; seniors see senior content)
- Each module = 3–5 short lessons + 1 scenario + 1 reflection prompt + 1 action step
- Lessons use plain language (max Grade 8 reading level for teens; Grade 6 for seniors)
- No lesson should exceed 5 minutes of reading/interaction time

**Completion Indicators:**
- Green checkmark per completed lesson
- Progress bar per module
- Certificate of completion (shareable, optional) upon finishing full audience module

**Training Does Not Replace Crisis Support:**
- Every training page carries a persistent crisis line link
- If a user flags distress during a scenario, the platform surfaces crisis resources immediately — training is paused, not ended

**Accreditation Note:**
- All training content is mapped to accredited references (see [Section 13](#13-accredited-references))
- GHCP must not modify training content without updating the reference mapping

## 5. Pet & Buddy System

The Pet & Buddy System is an engagement and accountability feature designed primarily for teen users.

**How It Works:**
- Upon first login, users choose a digital "buddy" (a small illustrated animal companion)
- The buddy reacts to user choices in scenarios (happy, worried, confused, proud)
- Buddy reactions are NOT rewards/punishments — they are emotional mirrors designed to prompt reflection
- Buddies do NOT track or report user behavior

**Buddy States:**

| State | Trigger |
|-------|---------|
| Calm/Happy | Completed a lesson or made a safe choice in a scenario |
| Worried | Encountered a red-flag scenario and paused to reflect |
| Curious | Exploring a new topic for the first time |
| Proud | Completed a full module |

**Design Rules:**
- Buddy must never look threatening, judgmental, or scary
- Buddy must work in grayscale (accessibility)
- Buddy animations must be subtle (no flashing, no rapid movement — epilepsy-safe)
- Buddy is optional: users can disable it without losing functionality

**Accountability Link:**
- Buddy progress is linked to the accountability logic (see [Section 16](#16-accountability-logic))
- Parents who use the Parent Link Generation Flow see a summary of buddy state (not scenario details)

## 6. App-Specific Grooming and Pressure Patterns

This section documents recognized patterns by platform. GHCP must maintain this as a living reference. Content is general-educational (not legal advice).

### Instagram
- **Grooming:** DM escalation after public comment engagement; fake follower offers in exchange for photos; "collab" requests from unknown accounts
- **Pressure:** Like/follower counts weaponized for self-worth; stories used to create FOMO; unsolicited explicit DMs

### Snapchat
- **Grooming:** Streaks used to create emotional obligation; screenshot-proof environment exploited for coercive content sharing
- **Pressure:** Time-limited snaps create urgency and impulsivity; "disappearing" content used as false safety promise

### TikTok
- **Grooming:** Comment-to-DM escalation; "I noticed your video" openers; fake brand/agency accounts
- **Pressure:** Duet/stitch features used to publicly expose users; comment sections used for body shaming

### Discord
- **Grooming:** Server invites from strangers; role assignments used to create false community belonging; private channel escalation
- **Pressure:** Gaming community leverage ("you'll lose your rank if you don't"); admin power dynamics

### Roblox (younger users, ages 9–13 — included for parent guidance)
- **Grooming:** In-game gift giving; avatar customization requests; "meet me in this private world"
- **Pressure:** Virtual currency used as a coercive tool

### Minecraft / Gaming Platforms (general)
- **Grooming:** Voice chat escalation; real-life meetup requests framed as "gaming events"
- **Pressure:** Team exclusion threats; account sharing requests

### General Patterns (cross-platform)
- Love-bombing early in the relationship
- Requests to move to a more private platform
- Escalating personal questions over time
- Creating secrecy ("don't tell your parents about me")
- Offering gifts, money, fame, or opportunities

## 7. Safe / Suspicious / Red-Flag Mechanic

This is the core interactive safety-assessment tool. It appears in teen and senior modules.

### GREEN — SAFE
- Clear identity known to user
- No requests for personal information, images, or secrecy
- Communication happens in shared, observable spaces
- No urgency or pressure
- Interactions feel mutual and comfortable

### YELLOW — SUSPICIOUS
- Identity unclear or inconsistent
- Requests for personal info that feel unnecessary
- Communication pushed to private channels
- Slight urgency or flattery that feels disproportionate
- User feels mildly uncomfortable but can't explain why

> **Action:** Slow down. Talk to a trusted adult. Do not share more.

### RED — RED FLAG
- Identity is unverifiable or clearly false
- Explicit requests for images, location, money, or secrecy
- Threats (direct or implied) for non-compliance
- User feels scared, confused, trapped, or ashamed

> **Action:** Stop contact. Screenshot and save evidence. Tell a trusted adult or call a crisis line. Do not delete messages.

**UX Rules:**
- Never display red-flag content graphically or in a way that re-traumatizes
- Scenario text is always fictional and clearly labeled
- Users can exit any scenario at any time without penalty
- Crisis link activates automatically if user selects "I'm not okay" during any scenario

## 8. Mixed-Signal Rule

The Mixed-Signal Rule addresses the most common reason young people dismiss red flags: *"But they were also really nice."*

**Definition:** A person or situation may display both safe and red-flag behaviors simultaneously. Mixed signals do NOT cancel out red flags — they increase them.

**Core Principle:** Safety is not determined by the good moments. It is determined by whether the bad moments are present.

**How It's Taught:**

> *Scenario: "They send me sweet messages every day, but last week they asked me not to tell my parents about them."*
>
> User is asked: "Which tier does this situation fall into?"
>
> **Correct answer: RED FLAG**
>
> *Explanation: "When someone asks you to keep them a secret from people who love you, that is a red flag regardless of how kind they seem."*

**UX Implementation:**
- Mixed-signal scenarios always appear after the basic safe/suspicious/red-flag mechanic is introduced
- Users must complete the basic mechanic first
- Mixed-signal module includes a "Why this matters" explanation before the scenario

## 9. Parent Link-Generation Flow

Parents can generate a supervised link to share curated content with their child without requiring the child to create their own account.

**Flow:**
1. Parent registers on the Parent page (email + basic info — no child data collected at this stage)
2. Parent selects child's approximate age range (not exact DOB)
3. Platform generates a unique, time-limited link for the child's device
4. Child opens link → lands on age-appropriate teen module (no login required for child)
5. Child's module progress is anonymized and summarized in parent dashboard (topic completion only — no scenario responses)
6. Parent can revoke link at any time
7. Link expires after 30 days (renewable)

**Privacy Rules:**
- No child personal data is stored
- Parent sees: modules visited, lessons completed, buddy state
- Parent does NOT see: scenario choices, reflection responses, anything flagged as sensitive
- If child accesses crisis resources via the link, parent is NOT notified (child safety and disclosure rules apply)

## 10. Senior Module Flow

Seniors enter a dedicated, simplified module. Design follows senior UX principles (large text, slow pacing, high contrast, no jargon).

**Flow:**
1. Senior lands on Senior Page
2. Selects topic area: Scams | Romance Fraud | Tech Support Fraud | Phishing | Social Media Safety
3. Each topic = 3 short lessons (5 min max each) + 1 real-world example + 1 "What to do right now" action step
4. End of module: "Talk to someone" card with phone numbers (not just links)
5. Optional: Print-friendly version of key tips (PDF download)

**Design Rules:**
- Font minimum: 18pt equivalent
- No auto-playing media
- All buttons large, clearly labeled with both icon and text
- Avoid metaphors unfamiliar to older users ("phishing" must be explained on first use)
- Phone numbers always present — not every senior user is comfortable clicking links

## 11. Teen App-Selection Flow

Teens can self-select the app they want to learn about.

**Flow:**
1. Teen lands on "What's happening on your apps" section
2. Presented with app icons: Instagram | Snapchat | TikTok | Discord | Roblox | Gaming | Other
3. Teen selects one or more apps
4. Platform surfaces app-specific grooming and pressure patterns (from [Section 6](#6-app-specific-grooming-and-pressure-patterns))
5. Interactive: "Has this happened to you?" (yes / kind of / no — anonymous, no data stored)
6. Content adjusts to selected apps for the remainder of the session
7. If "Other" is selected: user enters platform name → platform shows general pattern guidance from [Section 6](#6-app-specific-grooming-and-pressure-patterns)

**UX Notes:**
- Voluntary, low-friction tool — not a mandatory gate
- Teen can change app selection at any time
- No app-selection data is stored or shared

## 12. Design Simplification Rules

These rules govern all design decisions across the ReadyOnline platform. GHCP must apply these rules to every page, component, and interaction.

### Language
- Max Grade 8 reading level for teen content
- Max Grade 6 reading level for senior content
- No legal, clinical, or tech jargon without plain-language explanation
- Use second person ("you") throughout
- Avoid passive voice

### Visual Design
- Maximum 3 primary colors per page
- Icons must always be accompanied by text labels
- No content hidden behind hover states (mobile-first)
- Minimum contrast ratio: 4.5:1 (WCAG AA)
- No flashing or rapid animation

### Navigation
- No more than 3 clicks from home to any core content
- Back button always visible
- Progress indicator on all multi-step flows
- Exit/skip option on every interactive module

### Content
- No section longer than 300 words without a visual break
- Bullet points preferred over dense paragraphs
- Key terms bolded on first use
- One clear call-to-action per screen

## 14. Crisis Support Placement

Crisis support must be present on every page. No exceptions.

**Placement Rules:**
- **Primary:** Top-right corner of every page (persistent, not scrollable away)
- **Secondary:** Bottom of every content page, before the feedback form
- **Tertiary:** Triggered automatically when a user selects a red-flag scenario response or selects "I'm not okay"

**Crisis Resources (US-focused, expandable):**

| Resource | Contact |
|---|---|
| 988 Suicide & Crisis Lifeline | Call or text 988 |
| Crisis Text Line | Text HOME to 741741 |
| NCMEC CyberTipline | 1-800-843-5678 / CyberTipline.org |
| RAINN Hotline | 1-800-656-4673 |
| FBI Tips | tips.fbi.gov |
| Local Emergency | 911 |

**Display Format:**
- Phone numbers always displayed as plain text (not just hyperlinks)
- Resources must be readable without JavaScript
- Language: *"You don't have to face this alone. Help is available right now."*

## 15. Police-Contact Guidance

ReadyOnline provides practical, non-intimidating guidance on when and how to contact law enforcement.

**When to Contact Police:**
- Someone has sent explicit images of or to a minor
- An adult is attempting to meet a minor in person after online communication
- A user has received threats related to images or personal information (sextortion)
- Someone is impersonating a user or using their images without consent
- A user is being stalked or tracked online

**How to Contact:**

| Channel | When to Use |
|---|---|
| Local non-emergency line | Situations that are concerning but not immediately dangerous |
| 911 | Immediate danger |
| FBI IC3 (ic3.gov) | Internet crimes: sextortion, fraud, exploitation |
| NCMEC CyberTipline | Child sexual exploitation specifically |
| Platform reporting tools | Always report within the app as well as to law enforcement |

**Evidence Guidance (teach users before they contact police):**
- Do NOT delete messages, photos, or accounts — these are evidence
- Screenshot conversations (date/time visible)
- Note the username, display name, and any profile links
- Write down what happened in your own words before calling

**Language Note:**
- Never use language that implies the user did something wrong
- Use "Contacting police is a brave and important step" framing throughout
- Acknowledge that this can feel scary — validate before instructing

## 16. Accountability Logic

The accountability system is designed to support, not surveil. It is built on earned transparency.

**Core Principles:**
- Accountability is opt-in for teens; parents can request a summary link but cannot force data access
- No keystroke logging, no message reading, no location tracking
- Summary data only: which modules were visited, which topics were explored, buddy state

**Parent Dashboard Shows:**
- Module completion status (completed / in progress / not started)
- Buddy emotional state (general — not tied to specific scenarios)
- Date of last login (not time or duration)
- Optional: Teen-generated summary they choose to share with parent

**Teen Controls:**
- Teen can see exactly what their parent dashboard shows
- Teen can add a personal note to their parent's dashboard
- Teen cannot hide crisis resource access (parents are informed only that crisis resources were accessed — not the details)

**Escalation Logic:**
- If a teen accesses crisis resources 3+ times within 7 days, a general "your child may need support" notification is sent to the parent — no details, just a prompt to check in
- This escalation is disclosed to the teen upfront during onboarding

## 17. Feedback Form Placement

**Purpose:** Continuous improvement, user experience, and content accuracy.

**Placement:**
- End of every lesson (optional 1-question micro-survey: "Was this helpful? Yes / Kind of / No")
- End of every module (full feedback form, optional)
- Every content page footer (link: "Help us improve this page")

**Full Feedback Form Fields:**
- What worked well (open text, optional)
- What could be clearer (open text, optional)
- How did this content make you feel? (emoji scale, optional)
- Would you recommend this to a friend? (Yes / Maybe / No)
- Anything missing? (open text, optional)

**Privacy:**
- Feedback is anonymous by default
- No IP address or device fingerprinting
- Users can optionally include contact info if they want a response

## 18. GHCP Workflow Instructions

This section governs how GitHub Copilot (GHCP) must interact with this document and the ReadyOnline codebase.

### Document Authority

- This document is the **single source of truth**. In any conflict between this document and a code comment, README, or verbal instruction, **THIS DOCUMENT wins**.
- Do not modify section content without updating the version number and date at the top of this document.

### Build Rules

- Every new page or component must reference its corresponding section in a comment at the top of the file:
  ```
  // ReadyOnline Master Context: Section 6 — App-Specific Grooming Patterns
  ```
- No hardcoded crisis line numbers — all crisis data must pull from `/data/crisis-resources.json` so it can be updated without a code deploy.
- All training content must be stored in `/content/` as structured markdown with frontmatter reference tags.
- Design simplification rules ([Section 12](#12-design-simplification-rules)) are enforced at the component level — GHCP must flag any component that violates them.

### Prohibited Actions

- Do not generate, store, or process any real user data in test or staging environments
- Do not create any feature that tracks individual user scenario responses
- Do not build any notification that reveals a child's specific crisis disclosure to a parent
- Do not implement auto-play media without an explicit off toggle

### PR Review Checklist

GHCP must verify before any PR is approved:

- [ ] Section reference comment present in all new files
- [ ] Crisis resources pulled from `/data/crisis-resources.json`
- [ ] Design simplification rules verified ([Section 12](#12-design-simplification-rules))
- [ ] Accredited reference tags updated if content changed ([Section 13](#13-accredited-references))
- [ ] No child personal data in any new data model
- [ ] Accessibility verified: contrast ratio, text labels on icons, no hover-only content

### Content Update Protocol

1. Identify which section(s) are affected
2. Update `/docs/ReadyOnline-Master-Context.md` **first**
3. Update the affected `/content/` files
4. Update reference tags in the content management system
5. Submit PR with section numbers in the commit message

## Appendix A: Glossary

| Term | Definition |
|---|---|
| Grooming | A process by which an individual builds trust with a child (or vulnerable adult) to facilitate exploitation |
| Pressure Tactics | Behaviors designed to compel compliance through urgency, fear, guilt, or manipulation |
| Mixed Signal | A situation where both reassuring and concerning behaviors are present simultaneously |
| Red Flag | A behavior or pattern that indicates significant risk and requires immediate action |
| Buddy System | ReadyOnline's optional engagement feature using an illustrated animal companion to mirror emotional states during learning |
| Parent Link | A privacy-preserving supervised link generated by a parent to share platform content with a child |
| GHCP | GitHub Copilot, the AI-assisted development tool used to build and maintain the ReadyOnline platform |
| Accredited Reference | A source organization or publication recognized by the platform as authoritative for its domain |
