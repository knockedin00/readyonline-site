The problem

Parents assume protections exist. They often do not.

Families should not have to discover a safety gap after a child has already entered an app.

01

App stores do not pass child-account signals to apps.

A child can download an app from a family-managed device without the app reliably knowing it is serving a child.

02

Apps do not automatically turn on child-safety features.

Safety controls may exist, but a family can be left to find, understand, and activate every setting one by one.

03

The burden falls on parents.

Parents reasonably expect family protections to carry into the apps their children download. Today, that connection is inconsistent.

The simple solution

One signal. Automatic protection.

App stores should send a child account signal to apps. When an app receives that signal, it should turn on all child-safety features automatically.

  1. 1Family creation already establishes a child account.
  2. 2The app store sends a simple child-account signal when that child downloads an app.
  3. 3The app automatically enables its child protections. Parents can still turn them off easily.

This uses age information already collected during family creation. No new data. No PII. No verification.

How Child Signaling Works

Child signaling is not new technology. It uses the same infrastructure app stores already use to send dozens of signals to apps every day.

01

OS-Level Child Account Flags Already Exist

  • Google Family Link and Apple Family Sharing already know which accounts are children.
  • The OS already knows which device belongs to which child and which apps were parent-approved.
  • No new data is created. No PII is shared.
02

App Stores Already Send Signals Constantly

Apps already receive:

  • device type
  • OS version
  • region
  • language
  • subscription status
  • parental approval flags
  • permissions
  • OS-level security flags

Child signaling is just one more flag.

03

Apps Already Have Child-Safety Modes Built In

  • Restricted mode
  • Private accounts
  • DM blocking
  • Search filtering
  • Content filtering
  • Friend request restrictions

The issue is they do not turn these on automatically.

04

No Age Verification Required

  • 65% of kids are already in Family Link or Family Sharing.
  • Their age is already known and approved by a parent.
  • No scanning, no ID upload, no biometrics, no new data collection.
05

No PII Shared

The signal contains only:

“child account = true”

Nothing else.

06

Implementation Is Trivial

For app stores:

  • Add a boolean flag to the entitlement payload.
  • Send it with the existing metadata bundle.

For apps:

  • Listen for the flag.
  • If child = true, enable child-safety mode.
  • Provide a parent override.
07

Supported by the Meta Landmark Case

  • Meta publicly stated that app stores should provide a reliable age signal.
  • This would allow apps to automatically enforce protections.
  • This directly supports ReadyOnline’s petition.
08

Creates Instant Industry Transparency

Once the signal exists:

  • Apps that care will enable protections.
  • Apps that don’t will be exposed.
  • Parents will see who prioritizes safety.
  • Regulators will see who is negligent.

Technical Briefing

Universal Child Signaling Standard

Page 1 — The Problem & The Infrastructure

The Problem

App stores do not pass child account information to apps. Apps do not automatically turn on child‑safety features. Parents assume protections exist — but they don’t.

The Infrastructure Already Exists

Both iOS and Android already maintain OS‑level child account flags through:

  • Google Family Link
  • Apple Family Sharing
  • Device setup flows
  • Parent‑approved app downloads

These systems already know:

  • which accounts are children
  • which devices belong to which child
  • which apps were approved by a parent

No new data is required. No new identifiers are created. No PII is shared.

Page 2 — The Signal & The App Response

The Child Signal

App stores already send dozens of signals to apps:

  • device type
  • OS version
  • region
  • language
  • subscription status
  • parental approval flags
  • permissions
  • OS‑level security flags

Child signaling is simply:

child_account = true

This flag is added to the existing entitlement payload apps already parse.

The App Response

When apps receive child_account = true, they automatically enable:

  • restricted mode
  • private accounts
  • DM blocking
  • search filtering
  • content filtering
  • friend request limits
  • visibility restrictions
  • simplified settings

These features already exist. They simply aren’t activated automatically.

Parents can override protections easily — and apps will make this simpler than the current maze.

Page 3 — Feasibility, Privacy, and Industry Impact

Feasibility

For app stores:

  • Add a boolean flag to the entitlement payload
  • Refresh it on the same cadence as other metadata

For apps:

  • Listen for the flag
  • Trigger child‑safety mode

This is standard engineering work.

Privacy & Data Minimization

The signal contains only:

child_account = true

No birthday. No name. No email. No identifiers. No cross‑app tracking. No new data collection.

Industry Impact

Once the signal exists:

  • Apps that care will turn protections on
  • Apps that don’t will be exposed
  • Parents will see who prioritizes safety
  • Regulators will see who is negligent

This is accountability.

Developer Implementation Guide +
Developer reference

Developer Implementation Guide — Child Signaling

Step 1 — Read the Entitlement Payload

Your app already parses metadata from the app store. Add one line:

const isChild = entitlement.child_account === true;

Step 2 — Trigger Child‑Safety Mode

If isChild is true:

enableChildSafetyMode();

Child safety mode should activate:

  • private account
  • DM restrictions
  • search filtering
  • content filtering
  • friend request limits
  • visibility restrictions
  • simplified settings

Step 3 — Provide Parent Override

if (parentOverride === true) {
    disableChildSafetyMode();
}

Step 4 — Listen for Refreshes

Apps already listen for entitlement refresh events. Child signaling uses the same cadence.

Step 5 — Log Activation for Transparency

This helps parents and regulators see compliance.
